# 文件索引与管理工具（File X-Ray）

> 项目仓库：https://gitee.com/odayou/file-x-ray

一个跑在你**本机**的工具：索引展示文件，允许你给每个文件加**备注**、**状态**和**主题标签**；对**语音 / 视频可一键转写成文字稿**；对**图片可 OCR 识别文字、对 PDF 可抽取内部文字**；按文件名 / 备注 / 内容 / 标签 / 转写文字 / 图中文字 / 类型全文搜索；快速预览图片·视频·音频·PDF·文本；勾选后**按原目录结构打包**（带走备注、标签、转写稿、OCR 文字与 PDF 正文）；每次搜索可存为**任务清单**并随时重试。

> 为什么 FastAPI 能操作你的文件？因为后端进程就运行在你的电脑上，拥有完整的系统文件权限；浏览器只负责界面和发请求，真正的扫描 / 读取 / 转写 / OCR / 打开文件夹 / 打包都在本地后端完成。

## 运行方式（源码）

需要 Python 3.9+。

```bash
pip install -r requirements.txt
# requirements.txt 已含：fastapi uvicorn faster-whisper pymupdf pytesseract pillow
```

**OCR 引擎（三级优先，扫描件 PDF 开箱即用）**：

1. **浏览器内置 OCR（零安装兜底）**：程序自带 tesseract.js WASM 引擎与中英文语言包（约 14MB，位于 `web/vendor/tesseract/`），**扫描件 PDF 无需安装任何东西即可识别**——与 Edge 端侧 OCR 思路一致：模型随程序分发、在浏览器里运行。
2. **推荐升级（中文更强更快）**：安装 [Umi-OCR](https://github.com/hiroi-sora/Umi-OCR)，启动其「HTTP 接口」后本工具自动优先调用。
3. **轻量原生兜底**：安装系统 `tesseract`（含中文包 `chi_sim`）。
   - Windows：`pip install tesseract` 不行，需到 [UB-Mannheim](https://github.com/UB-Mannheim/tesseract/wiki) 下载安装，并把 `tesseract.exe` 所在目录加入 PATH。
   - Debian/Ubuntu：`sudo apt install tesseract-ocr tesseract-ocr-chi-sim`
   - macOS：`brew install tesseract tesseract-lang`

> 分工说明：**扫描件 PDF** 用任何一级引擎都能识别（浏览器内置兜底保证零安装）；**图片 OCR** 需要本机装有 Umi-OCR 或 tesseract（浏览器内置引擎暂不覆盖图片）。

启动：

```bash
cd file-index-tool
python backend.py
```

浏览器打开 **http://127.0.0.1:8000** 即可。默认感知本机回环地址，只有你自己能访问。

### 可选环境变量

| 变量                        | 默认值                                                            | 说明                                                                            |
| --------------------------- | ----------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| `FIT_DB`                  | `file_index.db`（打包后为 `~/file_index_data/file_index.db`） | 数据库文件路径                                                                  |
| `FIT_HOST` / `FIT_PORT` | `127.0.0.1` / `8000`                                          | 感知地址与端口                                                                  |
| `FIT_WHISPER_MODEL`       | `base`                                                          | 转写模型：`tiny`/`base`/`small`/`medium`/`large-v3`（越大越准越慢）   |
| `FIT_WHISPER_LANG`        | 空（自动检测）                                                    | 固定语种可填 `zh` / `en` 等，提升准确率                                     |
| `FIT_TRANSCRIBE_MAX_MB`   | `300`                                                           | 超过此大小的音视频文件跳过转写，避免卡死                                        |
| `FIT_OCR_ENGINE`          | `auto`                                                          | OCR 引擎：`auto`（优先 Umi-OCR，失败回退 tesseract）/ `umi` / `tesseract` |
| `FIT_UMI_OCR_URL`         | `http://127.0.0.1:1224`                                         | Umi-OCR 的 HTTP 接口地址                                                        |
| `FIT_OCR_LANGS`           | `chi_sim+eng`                                                   | tesseract 语言（多语言用 `+` 连接）                                           |
| `FIT_OCR_MAX_MB`          | `30`                                                            | 超过此大小的图片跳过 OCR                                                        |
| `FIT_OCR_PDF`            | `1`（开启）                                                      | 扫描结束后自动在**后台**对无文字层的扫描件 PDF 逐个 OCR（不拖慢扫描）；设 `0` 关闭 |
| `FIT_PDF_OCR_PAGES`      | `200`                                                            | 单个 PDF 的 OCR 页数上限（防超大扫描件拖死任务），`0` 不限制                      |
| `PDF_TEXT_LIMIT`          | `200000`                                                        | 单个 PDF 抽取文字上限（字符）                                                   |

## 项目：文件的自由组合

「项目」是一个**虚拟视图**，用来把散落在不同位置的文件归到一起看。它不是一个容器：

- **项目只记录一组根目录**，成员在查询时按路径前缀实时匹配 —— 所以新建项目、改名、改根目录都**立即生效，无需重新扫描**。
- **文件实体只有一份**。备注、状态、标签、转写稿、OCR 结果都跟着文件本身走，因此跨项目自动复用；项目之间可以任意交叉、嵌套、重叠。
- **目录结构按当前项目的根实时计算**。同一个文件在根目录不同的项目里显示各自的相对路径（例如根目录为 `D:\客户A\合同` 的项目里，`合同\a.pdf` 就显示为 `a.pdf`）。
- **同一个根目录反复扫描只刷新同一个项目**，不会堆出重复记录；项目只保留「最近扫描时间」。
- **删除项目只删除视图**，文件实体及其所有标注都会保留。
- 磁盘上已删除的文件默认隐藏（内部标记为「已失效」），点工具栏「👻 显示已失效」可显示出来，便于找回其备注。

> **旧库升级**：此前扫描过的根目录会在启动时自动转成项目，已有文件与备注、状态、标签一律不动。

### 根目录被改名 / 移动了怎么办

项目根目录被改名或移到别处后，项目面板会把该目录标红显示「**已失效：目录被改名或移动过**」，旁边出现「📍 重新定位」按钮：点它选中目录的新位置，索引会整体迁过去，**备注/状态/标签/识别结果一条不丢**。

即便不做这一步也丢不了东西：下次扫描时指纹会自动认出这些文件并迁移标注。

## 路径追踪：改名 / 移动不丢标注

文件在索引里是以完整路径作为身份的，路径一变按理会变成「新文件」，标注全部断开。本工具用**指纹**（文件大小 + 修改时间，必要时结合文件名）把「换了位置的老文件」认出来，**整行迁移**而非新建，所以备注、状态、标签、转写稿、OCR 结果全部跟着走：

| 场景                      | 处理                                                 |
| ------------------------- | ---------------------------------------------------- |
| 文件改名 / 移到别的目录   | 重新扫描时自动认出并迁移标注                         |
| 文件所在目录改名 / 移动   | 整个目录下的记录一起迁过去                           |
| 项目根目录整体改名 / 移动 | 扫描新位置时自动迁移；或直接在项目面板「📍重新定位」 |
| 开着实时感知时改目录名    | 感知直接处理目录移动事件，路径即时更新（无需等扫描） |

- **有副本也不会认错**：只有「旧位置的文件确实已经不在了」才迁移，仍然存在的副本不会被抢走标注。
- **无法区分时不猜**：多个文件指纹完全相同且都已消失时，宁可不迁移，也不会搬错。
- 指纹只用大小和修改时间，**不读取文件内容**，所以扫描速度不受影响。

### 典型用法

| 场景                    | 做法                                                        |
| ----------------------- | ----------------------------------------------------------- |
| 一个客户 / 课题一个项目 | 新建项目，根目录指向该目录                                  |
| 同一主题横跨多个盘      | 一个项目添加多个根目录（如 `D:\合同` + `E:\归档\合同`） |
| 只想盯某个子目录        | 新建项目指向该子目录即可，已索引的文件立刻可见，无需重扫    |
| 临时归集一批文件来处理  | 建项目 → 处理 → 删项目；文件与标注不受影响                |

## 图片 OCR 与 PDF 文字提取

### 图片 OCR（图中文字 → 可搜索）

- **引擎优先级**：默认 `auto`——先尝试本机已启动的 **Umi-OCR HTTP 接口**（中文识别更强、开箱即用），不可用时自动回退到本地 **tesseract**。可用 `FIT_OCR_ENGINE=umi` / `tesseract` 强制指定。图片 OCR 需本机装有其一（浏览器内置引擎仅覆盖扫描件 PDF）。
- **Umi-OCR 接入**：下载运行 [Umi-OCR](https://github.com/hiroi-sora/Umi-OCR)，在「全局设置 → 开启 HTTP 服务」后，本工具即可通过 `http://127.0.0.1:1224/api/ocr` 调用；语言由 `FIT_OCR_LANGS` 映射（如 `chi_sim+eng` → `ch_and_en`）。
- **tesseract 兜底**：需系统安装 tesseract 及 `chi_sim`（中文）语言包（见上方安装说明）。
- **触发**：右栏选中图片点「🖼 识别图中文字」，或勾选多个后点工具栏「🖼 识别选中图片」批量识别；非图片自动跳过。
- 识别结果写入索引中的 `transcript` 字段，之后按图中文字即可搜到该图片；导出时一并带走。

### 识别结果先暂存、再确认

OCR 与转写都遵循同一条规则：**已有旧内容时，新结果绝不直接覆盖**。

- **首次识别**（此前没有内容）：结果直接生效，不打扰你。
- **再次识别**（已有内容）：新结果进入**暂存区**，详情面板会以黄色区块显示，上方仍是当前生效的正式内容，方便对照。
  - 可以在暂存区里**直接改**（比如修掉识别错的字），再点「✓ 采用此版本」让它正式生效；
  - 点「✗ 丢弃」则保留原内容，暂存清空。
- **识别失败时不会写入任何东西**，旧内容完好无损（错误信息只记在任务结果里）。
- 清单中有待确认结果的文件，文件名后会带一个「待确认」标记。

> 不做识别历史留档：识别的旧版本一旦被采用即被替换。这是刻意的取舍——文件本身在软件之外会被反复修改，留在库里的历史必然不完整，不完整的历史没有参考价值。

### PDF 文字提取（内部文字 / 扫描件 OCR → 可搜索）

- **有文字层的 PDF**：扫描时**自动**用 PyMuPDF（回退 pypdf / pdfminer）抽取文字层，写入索引的 `content` 字段，无需手动操作。
- **扫描件 / 无文字层 PDF**：扫描只做快速的文字层抽取，**扫描结束后**自动在后台对无文字的 PDF 逐个「渲染每页 → OCR」，进度在 OCR 浮层实时显示（可点「转入后台」，完成时自动提示）。结果同样写入 `content`。
- **零安装兜底**：本机没有任何 OCR 引擎时，程序自带的**浏览器内置 OCR**（tesseract.js WASM，随 exe 分发）会接管扫描件 PDF 的识别——后端把每页渲染成图片，浏览器 Worker 里逐页识别后回传入库。速度比原生引擎慢（单页约 1~3 秒），装 Umi-OCR 后自动切回原生引擎。
- **存量补识别**：先扫描、后装引擎也没关系——装好后顶栏徽标变为「OCR ✓ · N 待识别」，点击即可对全部存量扫描件一键批量补识别；每次扫描结束也会自动补齐。
- **文字来源标记**：右栏 PDF 文字会标注来源——`文字层精确抽取` / `OCR 识别（建议校对）` / `人工校对`；OCR 结果附「🔍 对照原文校对」一键进入校对模式（左侧原文右侧文字并排修改）。
- **没有装 OCR 引擎时**：不会报错，只是扫描件 PDF 抽不到文字；此时右栏会显示黄色安装引导，顶栏的「OCR ✕ 未启用」徽标也可点击查看按系统（Windows / macOS / Linux）对应的安装步骤。

## 打包成 Windows 免安装 exe（双击即用）

本仓库已内置 PyInstaller 配置，在 **Windows** 上执行：

```bat
pip install pyinstaller
pyinstaller build.spec 或 python -m PyInstaller build.spec
```

生成的 `dist\文件索引工具.exe` 双击即可运行——它会自动启动服务并打开浏览器。数据库默认放在用户目录 `~/file_index_data/file_index.db`，不会因程序目录只读而报错。

> 说明：PyInstaller 不支持跨平台编译，需在与目标系统相同的系统上打包（在 Windows 上打 Windows 包）。本沙箱为 Linux，无法直接产出 exe，故只提供配置与步骤。

## 已知范围与扩展建议

- **图片 OCR / 语音视频转写是按需触发**；扫描件 PDF 的 OCR 在**扫描结束后自动后台执行**（不拖慢扫描，前提是本机已安装 OCR 引擎，见上方安装说明）。
- **OCR 引擎需本机自装**：默认不内置，按界面顶栏「OCR 状态」徽标或详情页引导，在 Windows 装 Umi-OCR / Tesseract、macOS `brew install tesseract tesseract-lang`、Linux `apt install tesseract-ocr tesseract-ocr-chi-sim` 即可，安装后刷新页面生效。
- 单个文件内容索引上限 20 万字符、大于 5MB 的文本文件不索引内容（可在 `backend.py` 调整 `CONTENT_INDEX_LIMIT` / `FILE_READ_LIMIT`）。
- 搜索结果列表单次最多返回 500 条用于展示，统计数字是全量匹配数。
- 数据库为单个 SQLite 文件，可随时删除后重新扫描。
